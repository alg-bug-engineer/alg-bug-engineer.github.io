# 视图逻辑优化说明

## 问题描述

用户反馈：输入"今晚六点开会"这样的今日事项，在今日面板没有呈现。

## 问题分析

### 原有逻辑的问题

#### 1. 今日视图（getTodayItems）
**原逻辑**：
- 只查询 `due_date` 在今天00:00:00到明天00:00:00之间的task和event
- **问题**：如果AI没有正确识别时间，导致due_date为null，这些条目就不会显示

#### 2. 收件箱视图（getInboxItems）
**原逻辑**：
- 只显示type为note和data的条目
- **问题**：没有截止日期的task和event无处可去

#### 3. 即将发生视图（getUpcomingItems）
**原逻辑**：
- 查询due_date >= 明天的task和event
- 这个逻辑相对合理，但缺少调试信息

## 优化方案

### 1. 今日视图优化 ✨

**新逻辑**：今日视图现在包含三类条目

#### 类型1：今天有截止日期的任务和事件
```typescript
// 查询条件
type: ['task', 'event']
due_date >= 今天00:00:00
due_date < 明天00:00:00
```

**示例**：
- "今晚六点开会" → AI识别为event，due_date为今天18:00
- "今天下午完成报告" → AI识别为task，due_date为今天

#### 类型2：今天创建但没有截止日期的任务和事件
```typescript
// 查询条件
type: ['task', 'event']
due_date: null
created_at >= 今天00:00:00
created_at < 明天00:00:00
```

**示例**：
- "今晚六点开会" → 如果AI没能识别时间，due_date为null
- 但因为是今天创建的，仍然会显示在今日视图
- 用户可以手动编辑补充时间

#### 类型3：过期但未完成的任务
```typescript
// 查询条件
type: 'task'
status: 'pending'
due_date < 今天00:00:00
due_date: not null
```

**示例**：
- 昨天的任务还没完成 → 继续显示在今日视图提醒用户

### 2. 收件箱视图优化 ✨

**新逻辑**：收件箱现在包含两类条目

#### 类型1：笔记和资料
```typescript
// 查询条件
type: ['note', 'data']
```

**示例**：
- "记录一个想法" → AI识别为note
- "保存这个链接" → AI识别为data

#### 类型2：没有截止日期的任务和事件
```typescript
// 查询条件
type: ['task', 'event']
due_date: null
```

**示例**：
- "今晚六点开会" → 如果AI没能识别时间
- 会同时显示在：
  - **今日视图**（因为今天创建）
  - **收件箱**（因为没有截止日期）
- 用户可以在任一视图中编辑补充时间

### 3. 即将发生视图（保持不变）

**逻辑**：
```typescript
// 查询条件
type: ['task', 'event']
due_date >= 明天00:00:00
```

**示例**：
- "明天下午开会" → AI识别为event，due_date为明天
- "下周一交报告" → AI识别为task，due_date为下周一

## 使用场景示例

### 场景1：AI正确识别时间

**用户输入**：
```
今晚六点开会
```

**AI处理结果**：
```json
{
  "type": "event",
  "title": "开会",
  "due_date": "2025-10-27T18:00:00.000Z",
  "created_at": "2025-10-27T10:30:00.000Z"
}
```

**显示位置**：
- ✅ **今日视图**（类型1：今天有截止日期）
- ❌ 即将发生视图（不是明天及以后）
- ❌ 收件箱（有截止日期）

---

### 场景2：AI未能识别时间

**用户输入**：
```
今晚六点开会
```

**AI处理结果**：
```json
{

  "title": "今晚六点开会",
  "due_date": null,
  "created_at": "2025-10-27T10:30:00.000Z"
}
```

**显示位置**：
- ✅ **今日视图**（类型2：今天创建无截止日期）
- ❌ 即将发生视图（没有截止日期）
- ✅ **收件箱**（类型2：无截止日期的event）

**用户操作**：
- 在今日视图或收件箱中看到这条记录
- 点击编辑，手动设置时间为18:00
- 设置后，会从收件箱消失，只在今日视图显示

## 优化效果

### 1. 解决了"今晚六点开会"不显示的问题 ✅

**原因**：
- 即使AI没能识别时间（due_date为null）
- 因为是今天创建的，会显示在今日视图
- 同时也会出现在收件箱，方便用户补充信息

### 2. 过期任务不会被遗忘 ✅

**原因**：
- 过期但未完成的任务会继续显示在今日视图
- 红色边框提醒用户注意

### 3. 收件箱更加智能 ✅

**原因**：
- 不仅包含笔记和资料
- 还包含没有明确时间的任务和事件
- 成为真正的"待处理"区域

### 4. 调试更加方便 ✅

**原因**：
- 控制台输出详细的查询条件和结果
- 方便排查问题和优化逻辑

## 技术细节

### 去重逻辑

今日视图可能从三个查询中获取数据，需要去重：

```typescript
const allItems = [
  ...(Array.isArray(withDueDate) ? withDueDate : []),
  ...(Array.isArray(withoutDueDate) ? withoutDueDate : []),
  ...(Array.isArray(overdueItems) ? overdueItems : [])
];

// 使用Map去重（基于id）
const uniqueItems = Array.from(
  new Map(allItems.map(item => [item.id, item])).values()
);
```

### 时间处理

```typescript
const today = new Date();
today.setHours(0, 0, 0, 0);  // 今天00:00:00

const tomorrow = new Date(today);
tomorrow.setDate(tomorrow.getDate() + 1);  // 明天00:00:00
```

### 排序逻辑

- **今日视图**：按due_date升序（有截止日期的优先）
- **即将发生视图**：按due_date升序
- **收件箱**：按created_at降序（最新的在前）

这次优化主要解决了以下问题：

1. ✅ **今日事项不显示** → 增加了今天创建但无截止日期的条目
2. ✅ **过期任务被遗忘** → 过期未完成的任务继续显示
