## ✨ 详细功能说明

### 对话式查询功能

#### 触发方式
- **特殊前缀**: 输入 `?` 或 `/q` 开头
- **自然语言**: 包含查询关键词(查询、查看、搜索、今天、本周等)

#### 查询示例
```
? 今天有什么事?
? 查询本周的会议
? 下周的任务
? 标签:工作
/q 明天的日程
```

#### 查询流程
1. 用户输入查询语句
2. AI识别查询意图
3. 解析查询参数(时间、类型、标签)
4. 执行数据库查询
5. 浮层展示结果

#### 查询类型
- **today**: 今天的事项
- **upcoming**: 即将发生的事项
- **week**: 本周的事项
- **month**: 本月的事项
- **type**: 按类型查询(task/event/note/data/url)
- **tag**: 按标签查询
- **general**: 通用关键词查询

#### 结果展示
- 浮层形式,不污染主视图
- 使用ItemCard和URLCard统一展示
- 显示查询摘要和结果数量
- 支持ESC键或点击外部关闭
- 支持在结果中直接操作(编辑、删除)

#### 用户体验
- 输入框边框高亮(查询模式)
- 图标切换(搜索/发送)
- 实时提示文本
- 流畅的动画效果

### 冲突事项高亮功能

#### 冲突检测
- **自动触发**: Event类型创建或更新时
- **检测算法**: 时间重叠判断
  ```
  A的开始 < B的结束 且 A的结束 > B的开始
  ```
- **批量更新**: 所有冲突条目同步更新状态
- **智能清除**: 冲突解除后自动恢复

#### 视觉警告
- **红色边框**: `border-l-4 border-l-red-500`
- **警告图标**: AlertTriangle (红色)
- **Tooltip提示**: "⚠️ 此日程存在时间冲突"
- **优先级**: 冲突警告优先于优先级颜色

#### 数据库实现
- **触发器**: `trigger_check_event_conflicts`
- **函数**: `check_event_conflicts()`
- **字段**: `has_conflict` (boolean)
- **索引**: `idx_items_has_conflict`

#### 使用场景
```
场景1: 创建冲突日程
1. 已有日程: 今天14:00-15:00 团队会议
2. 新建日程: 今天14:30-15:30 客户拜访
3. 系统检测到时间重叠
4. 两个日程都显示红色边框和警告图标
5. 鼠标悬停查看冲突提示

场景2: 解决冲突
1. 编辑其中一个日程
2. 修改时间避免重叠
3. 系统自动清除冲突状态
4. 红色边框和图标消失
```

### 数据库架构扩展

#### 新增字段

**冲突检测相关**
- `has_conflict` (boolean) - 是否存在时间冲突
- `start_time` (timestamptz) - 日程开始时间
- `end_time` (timestamptz) - 日程结束时间

**重复任务相关**
- `recurrence_rule` (text) - 重复规则(RRULE格式)
- `recurrence_end_date` (timestamptz) - 重复结束日期
- `master_item_id` (uuid) - 母版条目ID
- `is_master` (boolean) - 是否为母版条目

#### 性能优化
- 为所有新字段创建索引
- 触发器优化查询性能
- 批量更新减少数据库操作

#### 未来支持
- 日历视图数据结构就绪
- 重复任务字段完备
- 详细实现指南已提供

## 💡 使用建议

### 最佳实践
1. **查询功能**: 使用 `?` 前缀快速查询,避免切换Tab
2. **冲突管理**: 创建日程时注意红色警告,及时调整
3. **时间管理**: 为Event类型设置精确的start_time和end_time
4. **标签组织**: 合理使用标签,便于按标签查询

### 注意事项
1. 查询前缀 `?` 或 `/q` 必须在开头
2. 冲突检测只对Event类型生效
3. start_time和end_time必须同时设置
4. 查询结果最多显示100条
